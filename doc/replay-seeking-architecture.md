# Replay seeking architecture

Status: design draft (2026-07-05), no code. Companion to `sim-draw-thread-decoupling-research.md` — seeking is the chosen driving use case for the sim|draw boundary; it forces exactly Phases 0–1 of the split but ships as a user-visible feature with zero game-compat blast radius.

## The reframe

Seeking is hard today because one machine does two jobs: the sim both *is* the world state and *produces* the pictures, so "show frame N" means "get the entire deep sim state to frame N" (checkpoint + resim, fighting the render loop for the main thread). Split the jobs:

- **Watching** = rendering observable state → served by a recorded stream (snapshot keyframes + dirty field deltas). Random access, video-player semantics, no sim.
- **Being at a frame** = full deep sim state → creg checkpoint + resim, needed only to *resume* full inspection/play from the seek target.

Almost all of seek UX is the first job:

```
user drags scrub bar
├─ preview while dragging   ← stream keyframes, instant
├─ release at frame F       ← stream renders F immediately; camera, selection,
│                             info panels, minimap all work (spectator surface
│                             = observable surface; picking = boundary snapshot)
└─ background               ← resim from nearest checkpoint toward F; when sim
                              reaches F, swap feed stream → live sim, invisibly
```

## Components

1. **Recorded observable stream** — keyframes (full snapshot) + per-sim-frame dirty deltas of extracted fields (pos, health, team, defID, losStatus, piece transforms, optionally command queues). Engine-version-local format (replays pin engine versions → zero cross-version compat burden). Generated by an offline/headless index pass over the demo at max speed (`/setspeed` machinery); a regenerable local cache, deletable, never distributed. Demos stay the exchange format; for bug hand-off, clip keyframe + a few seconds of deltas (demo-sized).
2. **creg checkpoints** (existing, debugged through three rewind-desync classes) — the full-state anchors for background resim. Written during the same index pass.
3. **Background resim** — bridges displayed frame to live sim state. Initially main-thread with existing speed hacks; later the sim thread makes it invisible (draw stays interactive during resim).
4. **Draw-side reset hook** — after a jump, rebuild frame-over-frame draw accumulators from the keyframe: ghosted buildings, decals/trails, fades, tracked-camera targets. The one genuinely new piece; same hook class as `/luaui reload` recovery. The full accumulator inventory is below ("Reset-hook inventory", PR 21a).

## What works stream-fed

Camera: unconditionally (rendering is viewpoint-independent of the data feed). Clicking/selection: yes — picking runs against the boundary snapshot (positions, radii, collision volume params, piece transforms — if it renders, it raycasts); box-select via a draw-side grid over snapshot positions. Info panels, minimap, LOS view: snapshot-served. Command queues / order lines: only if queue deltas are in the recording profile (cheap — dirty-versioned, order-rate-bounded). Sim-only callouts (pathing, script state): degrade per the documented boundary contract (deterministic stale/nil + dev warning — no-lock decision in `sim-draw-thread-decoupling-research.md`). A spectator only ever touches observable state, so the whole spectator surface comes along by construction.

Explicit non-goal: **reconnect-to-live-game cannot use the stream.** Reconnect requires bit-identical deep sim state on the joining client; the stream carries neither the deep state nor enough to reconstruct it. Reconnect stays full-resim (or future creg-state-transfer).

## Decisions

Boundary-wide decisions — no lock fallback / boundary completeness, dirty-versioning + immutable shared blocks, the per-callout contract — live in `sim-draw-thread-decoupling-research.md` (decisions addendum + §D/§E). Seeking-specific:

- **Keep digests, regenerate data**: determinism means recorded state is exchangeable for recomputed state — persist hashes/keyframes, re-derive heavy data on demand (offline resim substitutes for retention). This is why the stream is a deletable local cache and demos stay the exchange format.

## Sizes (S0 measurements, 2026-07-05)

Measured over the full length of two 8v8 BAR replays (engine 2026.06.10 demos, resimmed headless with the S0 instrumentation: `/boundarydump` + `/calloutcensus`, `test/s0-measurement/`): **Rosetta 1.4.4** (44,537 frames ≈ 24.7 min, units mean 959 / p99 1757 / max 1843) and **All That Glitters Extended** (44,856 frames, units mean 1954 / max 3019). Stats below quote full-run mean and p99 per sim frame; late-game (last third) means are 1.3–1.6× the full-run means, well inside the p99s. Both resims were sync-clean (matching demo checksums end to end) with all instrumentation armed, and the per-frame sampler costs 0.02–0.05 ms (self-measured).

- **Hot fields** (pos, speed, health, heading, buildProgress; exact-change compare per unit per frame): delta payload mean 5.4–9.7 KB/frame, p99 ~20 KB/frame — about 5 B/unit/frame. Per-field change rates: pos ~21% of units per frame, speed ~15%, heading ~11%, health ~3%, buildProgress ~3%. The ~100–200 B/unit resident estimate stands for the full Lua-serving field set (measured subset is 38 B/unit), so a 10k-unit snapshot stays 1–2 MB — but the *per-frame delta* is only ~50–100 KB at that scale. Estimate: confirmed for snapshots, ~20× overestimate if applied to deltas.
- **Piece poses** (per-sim-frame model-space transform compare, sim-side so exact at any replay speed): active units average 6.4–7.7 pieces; 33–35% of piece transforms change per sim frame (p99 45–52%), on 45–48% of units. Raw dirty-delta payload at 32 B/`Transform`: mean 95–161 KB/frame, p99 282–330 KB/frame → 3–5 MB/s at 30 Hz ≈ 10–17 GB/h raw at the 2–3k-unit scale. The old "~10–20 MB/frame raw at 10k units" figure was a 4–8× overestimate (it assumed 64 B matrices, no dirty-skip): measured full-set upload is ~0.5–0.8 MB/frame at 2–3k units (`transformsMemStorage` resident peaks: 1.72 / 2.27 MB). Conclusion unchanged in kind, softer in degree: dirty-tracking alone gets to ~video bitrates, and pose quantization (~10 B/pose → 3–5 GB/h) remains the lever for the recording profile.
- **Command queues**: mutations mean ~10/frame (p50 3, p99 <100, burst max 8034 on mass orders); resident queue content mean 1.1–2.4k commands across 350–500 nonempty queues (p99 2.6–9.7k, longest single queue ~200–300). Order-rate ≪ frame-rate confirmed — dirty-versioned queue copies are noise-level work.
- **Projectiles**: synced live count is tiny (mean 45, p99 195–414, max 647). Synced spawns mean 1.5–2.3/frame, of which guided (tracking) is only 2–4% — ballistic + hitscan + piece, i.e. re-derivable-from-spawn-params or 1–2-frame-lived classes, are ≥96%. The unsynced particle population (live 3.4–5.6k, ~100+ spawns/frame) is draw-side-owned already and never crosses the boundary. The previously "unquantified" projectile churn hole is closed: record spawn params for ~2 projectiles/frame plus per-frame positions for the handful of guided ones — negligible against piece poses.
- **Unit/feature/LOS events**: unit create/destroy ~0.15/frame, features ~0.1/frame, LOS transitions <1/frame mean — noise as predicted, *but* bursty (max 2760 enter-LOS in a single frame at a game-end reveal): the delta queue and keyframe encoder must size for reveal bursts, not means. The in-engine event records now exist (PR 12, `RenderEventQueue::Record` in `rts/Rendering/Common/RenderEventQueue.h`): create/destroy/LOS-change as plain data keyed by object ID — the stream event schema starts from these types; the transitional object-pointer field disappears with PR 14.

Extraction cost: the S0 sampler's read-only walk over all units (hot-field compare + queue-length histogram) plus the per-piece transform compare lands at 0.02–0.12 ms/frame at 1–3k units, supporting the sub-ms linear-copy expectation for boundary extraction (`for_mt`-able with headroom at 10k).

## Reset-hook inventory (PR 21a, 2026-07-05)

Every draw-side structure that accumulates state frame-over-frame — i.e. whose correct value after a time-jump cannot be derived by just re-running the normal per-frame update against the restored sim state. Method: full sweep of `rts/Rendering/`, `rts/Map/` draw state, `rts/Game/UI/`, camera, and `rts/System/Sound/`, member-by-member, plus verification of what the creg checkpoint (`CGameStateCollector::Serialize`, `rts/System/LoadSave/CregLoadSaveHandler.cpp:80-115`) actually covers. This is the requirements list for PR 21b (the hook implementation); the stream-format flags feed PR 19.

**Two jump flavors.** A *checkpoint jump* restores full deep sim state via creg (the background-resim path); the creg collector already restores more than expected (below), so the hook handles the residue. A *stream jump* (scrub preview / render-at-F before resim catches up) replaces only the observable snapshot; there every event-maintained or history-encoding structure must be reset from keyframe data. Strategies below name the residual work; "ckpt" column = restored by the creg checkpoint today.

**Strategy vocabulary**: **recompute** = derivable from restored sim + LOS, hook recomputes or triggers an existing full-recompute path; **clear** = discard and let future events refill (bounded cosmetic gap accepted); **stream** = correct post-seek value needs history the keyframe must carry — input to PR 19; **leave** = wrong for a bounded time, self-heals, justified in Notes.

### What the creg checkpoint already restores (verified)

The collector serializes `gs`, `gu` (incl. `gameTime`), `game`, `readMap` (synced heights + metal extraction), `quadField`, unit/feature/LOS/team handlers, `waitCommandsAI`, `uiGroupHandlers` (control groups), `eoh`, **both projectile containers** (`CR_MEMBER(projectiles)` covers unsynced too, `ProjectileHandler.cpp:52`), **the unit-drawer ghost state** (`CUnitDrawer::modelDrawerData->GetSavedData()` — dead/live ghost buildings and temp draw units, `UnitDrawerData.cpp:75-81`), and **all ground decals** (`groundDecals`, with `PostLoad` re-uploading the VBO, `GroundDecalHandler.cpp:111-114`). `CUnit::PostLoad` / `CFeature::PostLoad` re-emit `Render*Created` through the event queue (`Unit.cpp:413-419`, `Feature.cpp:119`), repopulating drawer containers.

**Verified checkpoint gaps** (stale after a creg load today): no projectile `Render*Created` re-emit (`RenderProjectileCreated` fires only from `AddProjectile`, `ProjectileHandler.cpp:336` — restored projectiles never reach the drawer), `flyingPieces`/`groundFlashes` (`CR_MEMBER_UN`, `ProjectileHandler.cpp:53-54`), `geometricObjects` (absent from the collector entirely), `grassMap` and `SmoothHeightMesh` (see sim-side gaps below), selection, camera, unit tracker, minimap notes, info console, in-map drawings, player stats.

### Hook ordering (checkpoint-jump path)

1. Quiesce draw; drain `RenderEventQueue`, ack + release `DeferredObjectDeleter` (poison scan runs); `selectedUnitsHandler.ClearSelected()` (drops death-dependences off soon-to-die objects).
2. Evict the old world from event-maintained drawer containers (units/features/projectiles) — bulk reset primitive, `KillStatic(reload)`-class; frees the per-object SSBO slots.
3. Creg restore (brings both projectile containers, decals, ghosts, groups, `gu`; unit/feature `PostLoad` re-emits creates; projectiles need the new re-emit — checkpoint gap above).
4. Post-restore fixups: full-rect heightmap resync fires automatically (`ReadMap::PostLoad`); `MakeSmoothMesh()`; flush `GeometricObjects`; clear `flyingPieces`/`groundFlashes`; rebuild `liveGhostBuildings` from `losStatus`; clear temp draw units, both LightHandlers, minimap notes; re-latch `CUnitTracker`; mute sound across the jump.
5. Fire the Lua seek callin (below); run one extraction pass (`SimSnapshot` + transforms re-extract on their own via the frame-inequality triggers).

For a stream jump, steps 1-2 are the same; step 3 is replaced by snapshot/keyframe ingestion, and every "ckpt: yes" row above becomes keyframe data or a clear per its stream strategy.

### Stream-format implications (input to PR 19)

- Per-allyteam dead-ghost sets (pos/dir/radius/team/model of A1 ghosts) — needed only for player-POV seek; full-view spectating needs nothing.
- Decal state (scars/tracks with rebased age) — or accept clear-to-bare-ground on seek as a recording-profile choice.
- Demo side-channel events (chat, map drawings, minimap pings) — cheap to index by frame during the offline pass; without them a forward seek silently loses them.
- Unsynced particle population is *not* recorded — post-seek visuals refill from stream event records (explosions → CEG re-fire is PR 20 territory); document the brief "clean air" after a seek as accepted.
- Grass state (see below) — tiny bitmap, candidate for keyframe inclusion once the sim-side ownership is fixed.

### Sim-side checkpoint gaps discovered (filed here; not draw-reset work)

- **`grassMap` is synced-readable state stored in a drawer and serialized nowhere**: mutated by synced code (`BasicMapDamage.cpp:169`, `LuaSyncedCtrl.cpp:4615,4629`), read by synced Lua (`LuaSyncedRead::GetGrass`, `LuaSyncedRead.cpp:7846`), no creg. Any checkpoint load (including today's replay-rewind gate) restores a world whose grass differs from the original timeline — a latent resim-divergence source if a gadget reads `GetGrass`. Fix belongs sim-side (serialize it or move ownership out of `CGrassDrawer`).
- **`SmoothHeightMesh` is sim state consumed by synced code** (`AAirMoveType.cpp:57-60`) **but not creg-serialized**; after a load it converges back lazily (~1 s drain), during which synced consumers read values that differ from the original timeline. Candidate explanation-class for residual rewind drift; `MakeSmoothMesh()` after restore closes it.
- **No `RenderProjectileCreated` re-emit on creg load** (`PostLoad` gap) — restored projectiles are invisible to the drawer until this is added.
- **`GeometricObjects` absent from the collector** + exact-frame expiry — stale under every load path today.

### Lua/game-facing consequence (out of engine scope, must be documented for games)

Widget/gadget state is the one accumulator class the engine cannot reset: unit caches, GL4 instance buffers, particle emitters (`move-unsynced-gameframe-work-todo.md` documents exactly this state shape), `userDefined` object uniforms, Lua-registered dynamic lights. The seek must fire a to-be-defined callin — working name `GameFrameJumped(prevFrame, newFrame)` — with "treat like `/luaui reload`-lite" semantics: rebuild frame-keyed caches, re-add lights, re-populate custom uniforms. The playbook hazards in `move-unsynced-gameframe-work-todo.md` (exact-frame buckets, `n - prev` integration) are the same hazards widget authors must handle for jumps.

## Risks / open questions

- **QTPFS rewind accumulation** (`replay-rewind-qtpfs-accumulation-todo.md`) gets *more* exposed by dense seeking; S1 hashing is also the tool to finally localize it (space-level: which unit/field drifted).
- Reset-hook completeness: **inventory done (PR 21a, "Reset-hook inventory" above)** — the residual risk is now the flagged design decisions (player-POV ghost/decal data in the stream vs clear-on-seek) and the sim-side checkpoint gaps (`grassMap`, `SmoothHeightMesh`, projectile re-emit), not unknown accumulators.
- Piece-transform encoding is the remaining open format problem (S0 sized it: ~33% churn, quantization needed for the recording profile). Projectile encoding is closed by S0 — synced spawns are ~2/frame and ≥96% re-derivable; guided updates are a rounding error.
- Feed-swap seamlessness (stream → live sim at catch-up moment): interpolation continuity across the swap needs care.
