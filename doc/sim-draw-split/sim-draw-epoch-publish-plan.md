# Plan: epoch-published boundary — full tail serving, pointer-free draw, producer-side extraction

Status: plan only (2026-07-06). Companion docs: `sim-draw-thread-decoupling-research.md` (the landed PR 1–27b architecture this builds on), `pr27b-implementation-notes.md` (the working record of the current split), `replay-seeking-architecture.md` (the stream format the epoch package feeds).

## The two driving decisions (settled 2026-07-06)

1. **The Lua serving tail gets closed completely.** Every sim-reading callout, when invoked from unsynced context, reads the published boundary state — no deny-until-served nil shapes, no `sanctionedLive` live-read bridge, no `ScopedLiveException` for boundary dispatches. The target end state is an EMPTY sanctioned table: strict mode over a full replay + windowed dogfood with zero denials and zero sanctioned entries is the completeness proof (the same decision-5 shape as 27a, but with nothing left on the exception list).
2. **No pointer resolution through sim-owned tables, anywhere on the draw side.** Draw code never looks an id up in `unitHandler`/`featureHandler`/`projectileHandler` (or any other sim-owned map) after the split releases the sim. Draw passes, picking, decals, and Lua serving all read drawer-owned / epoch-carried data. The distinction that matters: *resolving through a sim-owned table* is banned; *holding a stable pointer whose lifetime the deferred-deletion epoch guarantees* is a documented interim only where extraction is measured too expensive (see the projectile decision below), and the goal is zero of those too.

Why these two together: most of the split's shakeout defects (died-in-burst nil shapes, the two snapshot-freshness gaps, the resolve-cache class, the tid-0 scratch collision from live Lua spatial walks) are consequences of draw code still touching live sim structures inside carve-outs. Closing both removes the carve-outs instead of patching their edges.

## Target architecture (the #4 end state)

- The sim thread produces a complete **boundary epoch** at its own frame edges: all SimSnapshot namespaces (grown to cover the whole served surface), the frame's render-event + deferred-unsynced-dispatch records, dirty-rect deltas for the map mirrors (heightmap, LOS, metal, blocking, smooth mesh), and rules-param/command-queue/path deltas. Epochs are N-buffered (start with 3) and refcount-retired.
- The draw side consumes the newest complete epoch. No park, no handshake on the hot path: "no new epoch" simply means re-rendering interpolation from the current one (the no-op-boundary and try-pause ideas fall out as the steady-state behavior).
- Event records ride the epoch that contains their frame and are never skipped: if draw falls behind, records from unconsumed epochs batch into the next consumed one (exactly today's batch-drain semantics, producer-side). Row data for ids that died within a consumed batch stays readable, flagged dead-in-batch, until that epoch retires — this replaces the shell-fallback machinery with plain data.
- Sim pacing: extraction is skipped while the previous epoch is unconsumed (extract at min(sim rate, draw rate) — a catch-up burst pays ~one extraction per draw frame, like today's batching). Backpressure becomes "sim runs ahead ≤ N-1 unretired epochs"; the pool-pressure valve becomes "sim waits for epoch retirement".
- `RequestPause` survives only for rare lifecycle quiescence: saves, checkpoint serialize, Lua handle reload, teardown, and armed test gates (the diff gate's field passes need a quiescent compare window; the gate parks, gameplay never does).

## Machinery this plan deletes (the simplification payoff)

- `sanctionedLive` table + `DenyLiveRead`'s strict-mode deny path for gameplay (kept only as the tripwire for future unclassified callouts — it should never fire).
- `ScopedLiveException` on the barrier/valve/a0 dispatches (handlers read the epoch; the pre-publish `Generation()==0` fallback stays for pregame only, where no sim thread runs yet).
- `SetBoundaryShellWindow` + `ShellFallbackUnit/Feature` + RenderEventQueue's dispatch-time id→shell maps (replaced by dead-in-batch row retention).
- `BuildSplitResolveCache` (units/features/projectiles) and every `DrawerGetObjectByID`-through-handler path (replaced by drawer-owned render records).
- The `MarkMutatedOutsideFrame` freshness pokes (ctrl pokes are applied by the sim thread before it extracts — freshness by construction; the net-mutation-between-frames case keeps one producer-side re-extract mark, see PR 44).
- The end-of-Draw `ReleaseAcked` special case and the valve's in-place drain service (epoch retirement is the single release point).

## Decision points (need a call before the affected PR)

1. **Unsynced `RequestPath` / `PathFinder` object API (PR 36).** Options: (a) boundary-deferred async — the returned path handle becomes valid one boundary later, nil-safe before that (documented deviation; matches the ctrl-poke latency model); (b) draw-side search over a movemap mirror (large: a traversability mirror + a second search instance); (c) deny with the dev warning (park the API for widgets). Demand is trace-level in both censuses. Recommendation: (a).
2. **`GetUnitMoveTypeData` (PR 32).** Full table copy per unit per boundary is the one unbounded-ish item in the deep-state family. Options: serve the documented common-subset fields as rows + full table via dirty-copy only for units a widget actually queried (interest flag); or full copy for all (measure first). Recommendation: interest-flagged.
3. **Weapon trace-test deviation envelope (PR 35).** Sign off that boundary-state results + snapshot trace order is acceptable fidelity for `TryTarget`-class callouts (they are advisory UI predicates; the synced weapon logic is untouched). The alternative — boundary-computing them via sim-side evaluation of queued queries — adds a request/reply channel for marginal fidelity.
4. **Projectile visual extraction budget (PR 40).** Extract-per-boundary POD packets are the clean end state; measure the copy cost on the S0 replays first (est. 1–2 MB/boundary at heavy particle counts, for_mt-able). If over budget, the documented interim is record-captured stable pointers under epoch lifetime (memory-safe, §C-torn) — never handler lookups. Decide the budget number.
5. **`SendSkirmishAIMessage` (PR 37).** Synchronous sim-side AI call from unsynced. Boundary-apply with a deferred (nil-now) result, or hard error under the split. Recommendation: boundary-apply + deferred result; it is the last synchronous sim entry on the ctrl surface.

## Verification strategy (what carries over, what changes)

- The armed diff-gate dual-run remains the per-family serving proof for all of Wave 5 — it runs single-threaded (flag OFF + contract), where its quiescence premise holds. Every new row joins the field passes; every twin gets dual-run counters; table-returning callouts use the structural compare; order-deviating families use set-mode.
- Strict mode is the completeness meter: the `sanctionedLive` table must shrink monotonically per PR and hit empty at 38. Any strict-mode denial after 38 is a bug by definition.
- The resim gates (both master demos, full-length, 0 DESYNC, flag OFF and ON) run per PR as today; DEBUG-headless + TSan segments re-run at 38, 43, 44 (the lifetime-model changes).
- Post-flip (44), the dual-run's live leg is gone for good; the diff gate's quiescent field passes survive under the retained lifecycle park (armed runs park the sim per compare window — test-only cost).
- Windowed dogfood gates at 29 (placement UI), 35 (targeting widgets), 37 (ordering widgets), 38 (full session, empty table), 44 (the flip). Gate verdicts grep `field=`/contract lines, not just DESYNC (the 27b lesson).

## Cost watchpoints

- Extraction time is the budget under pressure: 27a already grew it to 0.33/0.75 ms avg (Rosetta/ATG) and Wave 5 adds weapons/queues/deep-state/mirror drains. Per-PR telemetry (the PR-1 instrumentation) tracks the per-boundary avg/max; dirty-versioned families must demonstrate mutation-rate (not frame-rate) cost. If the summed boundary cost approaches ~1.5–2 ms, revisit SoA layout / for_mt extraction before the flip — under the producer model this becomes sim-frame budget, where 2 ms of a 33 ms frame is acceptable but not free.
- Resident memory: snapshot doubled-buffers grew 2×1.5 MB → 2×~22 MB through 27a; epochs at N=3 multiply the per-epoch payload. Delta/refcount sharing (queues, paths, rules params) is what keeps N-buffering cheap — flat rows stay flat-copied, everything unbounded shares.
