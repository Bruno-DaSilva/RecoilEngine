## Cross-cutting contracts (all PRs)

- Shared-file discipline, add-a-field recipe, POV/masking audit, deviation enumeration, commit style: per the plan doc's PR-plan preamble and the research doc's §E.2 recipe. Non-negotiable.
- **Dirty-tracking choke-point rule:** every mirror/dirty-copy in this program must funnel mutations through a small named set of marking functions, and the PR must include the grep-audit table (every writer of the mirrored state → which choke point covers it) in the commit message. A mutation path that can bypass the choke points is a design defect, not a runtime bug to find later.
- **Mirror verification rule:** every mirror gets a `SnapshotDiffGate` compare pass — at an armed quiescent boundary, bit-compare the full mirror against the live source (memcmp-grade). This converts the missed-dirty-mark class from "timing-dependent dogfood find" into "deterministic gate failure". Budget: compare passes are test-only cost, armed runs only.
- **Serving-twin fidelity rule:** a twin reproduces the live callout's exact Lua surface — table shape, key types, 1-based indexing, nil-vs-false, argument handling (count/limit args, optional team filters), and the live path's POV gate mapped to the snapshot Pov mirrors (`PovUnitVisible`/`PovAlliedUnit`/`PovUnitInLos`/`PovUnitTyped`/`PovFeatureVisible` + the alliance matrix). Any intentional difference is an enumerated deviation with the set-mode/structural compare called out.

## PR 30 — command queues (dirty-versioned immutable block pattern-setter)

Deliverable: the block store + serving twins for the whole queue/factory/cmdDesc family; the pattern PRs 31/32/36 copy.

- **Block store**: `SimSnapshot::CmdQueueRows` — per-unitID pointer to an immutable refcounted block `{u32 version; small_vector<CmdRecord> queue; std::vector<CmdDescRecord> descs...}`. Refcount is atomic (cheap now, required by Wave 7's cross-thread epochs — do not design it boundary-only). Double-buffered pointer arrays; clean units share the block across generations (bump ref), dirty units get a freshly built block at extraction.
- **Choke point — the queue type itself**: `CCommandQueue`'s mutating operations are the funnel. Make the raw container private; expose mutating methods that set an owner-dirty hook (a pointer-to-flag registered by `CCommandAI`). Every scattered `commandQue.push_back/pop_front/insert/erase/clear` across the CommandAI subclasses then either compiles against the marking methods or breaks — the compile-caught design the plan calls for. `possibleCommands`/cmdDescs mutations funnel through the existing `CCommandAI` description-update methods; add the dirty hook there (separate flag: desc blocks change far less often than queues — split the block in two so a queue pop doesn't recopy descs).
- **CmdRecord**: id, options, tag, params (inline small array + overflow) — enough to reproduce `GetUnitCommands`' full table shape including `params` arrays and `options` sub-table encoding. Copy from `Command` verbatim; no interpretation.
- **Twins** (each with the live path's exact shape — check the C code, not the wiki): `GetUnitCommands`/`GetCommandQueue` (count arg semantics incl. `-1` and `0` forms), `GetUnitCommandCount`, `GetUnitCurrentCommand` (1-based index arg), `GetFactoryCommands` (its distinct shape), `GetFactoryCounts`, `GetFactoryCommandCount`, `GetFactoryBuggerOff`, `GetFullBuildQueue`/`GetRealBuildQueue` (the aggregation loops re-hosted over the block), `GetUnitCmdDescs` (1-based slicing), `FindUnitCmdDesc`, `GetUnitWorkerTask` (builder current-task read — the fields it reads join the deep-state rows if not derivable from the queue block; check first, escalate if neither).
- **Factory quirk**: factory queues live on the factory's CommandAI with repeat/count encoding in options/params — the twins must reproduce the live decoding, not reimplement it; lift shared decode helpers where the live path has them.
- **Telemetry**: extend `BoundaryStats` with blocks-copied/bytes-copied per boundary; the acceptance number in the plan (cost tracks order rate) comes from the two gate replays.
- Deviations expected: none pre-split (extraction reads the same completed frame the live reads saw). State after verifying.

## PR 38 — zero-sanction flip + dead-in-batch retention

## PRs 43/44 — epoch infrastructure + producer flip (contract level; Opus fills mechanics from landed reality, escalates protocol changes)

- **Epoch** = `{u64 id; snapshot generation (all namespaces); renderEvent + a0 records for its frame span; mirror dirty-rects; delta-block refs (queues/paths/rules); dead-in-batch id list}`. N=3 ring. Draw acquires newest-complete (refcount++), releases previous (refcount--). `DeferredObjectDeleter` frees a shell when the last epoch referencing its destroy record releases. Records are never skipped: an unconsumed epoch's records fold into the next published epoch (batch semantics preserved).
- **43 lands the representation under the existing park** (flag-on behavior identical, TSan re-run); **44 moves production to the sim thread**: extract at the frame edge iff the previous epoch was consumed (min-rate pacing); net-mutation-between-frames re-marks the pending epoch (the `MarkMutatedOutsideFrame` successor, producer-side); ctrl-poke queue consumed by sim immediately before extraction (freshness by construction); `RequestPause` demoted to lifecycle + armed-gate use only.
- **Protocol invariants 44 must keep** (escalate if any is threatened): draw never blocks on sim; sim blocks only on epoch-ring exhaustion (backpressure) or pool valve (now = wait for epoch retirement); event-record fire order is total and preserved across fold-ins; flag-off remains bit-identical.

## Batch-3 amendment (2026-07-07, operator ruling; BINDING, supersedes the PR-35 section above)

A faithful draw-side recompute would also require reproducing the entire ballistics+collision subsystem (~30 new snapshot fields, the 4 virtual `GetPredictedImpactTime` overrides, `GetAccuratePredictedImpactTime` gravity iteration, error-pos, target-border collision raytrace, per-unit AND per-feature collision volumes) — large, fragile, enormous diff-gate surface.   Binding mechanism shape (the impl agent designs specifics, following the landed Route()/twin + boundary-drain patterns):
  - **Flag-OFF**: the callout runs the LIVE predicate directly (`CWeapon::TryTarget/TestTarget/TestRange/HaveFreeLineOfFire`), exactly as master — bit-identical, no queue, no defer. Route() for these four dispatches to the live predicate when the split is off, NOT to a snapshot value.

The SIM thread, at its frame edge, drains pending queries, evaluates the EXACT live predicate against live sim state, and writes results into a draw-readable reply map keyed by the query. Boundary-deferred (≤1 boundary stale) but SIM-EXACT — no approximation. First-call/miss returns a documented default matching master's "no target" answer (false / nil / 0 as appropriate). Reply state is UNSYNCED (draw-only): no synced write, no gsRNG, no streflop.
  - **Query stability**: targeting/placement widgets call these per-frame with stable args, so the deferred reply is populated after frame 1; document the first-frame default.
  - **Diff-gate**: the armed gate is a flag-OFF resim, where the query/reply is synchronous (sim==draw thread) and returns live-exact → passes trivially. ## PR-38 event-time mechanism generalization (Fable ruling, 2026-07-07; BINDING for batch 4, operator may override on review)

Headful attrition (batches 1–3) showed three flag-ON widget Lua errors that are ONE class — synced-EVENT callins whose unsynced handlers read state that changed AT the event, which boundary serving presents stale/nil:
- `unit_ghostradar_gl4` UnitLeftLos → position (the LOS-exit case already in amendment (b));
- `gui_selfd_icons` UnitCommand → command queue (`attempt to get length of cmdQueue (nil)`);
- `unit_idle_guard` UnitCmdDone → command queue/count (`attempt to compare number with nil`).

So PR 38's event-time-visibility mechanism GENERALIZES from LOS-only to a single **event-time state presentation** mechanism covering command-event callins too:
- **Keep** the LOS-exit visibility exception (amendment (b)) unchanged.
- **ADD command-event queue presentation.** When the sim records a `UnitCommand`/`UnitCmdDone` event for boundary dispatch, it also records that unit's command-queue state AS OF the event (content-version + the added/removed command, or a per-event queue snapshot — impl's choice, following the landed CCommandQueue content-version + the DEAD_THIS_BATCH dispatch-drain presentation from amendment (a)). At dispatch, the served command-queue cache for that unit presents the EVENT-TIME state for the duration of that handler call: `UnitCommand` → queue includes the just-added command; `UnitCmdDone` → queue reflects the just-completed command's removal — matching master's synchronous dispatch. Same per-unit dispatch-window override as DEAD_THIS_BATCH.
- **Contract**: `GetUnitCommands`/`GetCommandQueue`/`GetUnitCommandCount`/`GetUnitCurrentCommand` called from inside a command-event callin see the event-time queue, not the last-boundary queue. Unsynced (draw-only) — no synced write, no sync-hash impact, no gsRNG.
- **No approximation**: the presented state is sim-exact at the event (the sim recorded it). Enumerate the dispatch-window override as the deviation (like DEAD_THIS_BATCH).
- **Verification**: after PR 38, the full headful matrix (both replays, flag-ON) must clear ALL THREE (ghostradar, gui_selfd_icons, idle_guard). Because they are draw-timing-FLAKY (appear/vanish across runs), run the matrix MULTIPLE times / a long window to confirm they do not recur — a single clean run is not sufficient proof.
- Rationale for ruling inline rather than blocking on the operator: this extends an already-planned PR-38 mechanism to a demonstrably-identical input class (not a new architecture); it is reversible and gated by headful attrition; the operator's standing goal directive prioritizes progress. Operator may still override the mechanism on review.
