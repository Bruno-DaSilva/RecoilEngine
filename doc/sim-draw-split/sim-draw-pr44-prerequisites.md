## Gap A — UI control-groups → fully draw-owned (spec ready)

`uiGroupHandlers[].Update()` (CGame::UpdateUnsynced) reads/swaps draw-owned group containers the SIM thread also mutates. Groups are UI-owned + sync-invisible (`rts/Game/UI/Groups/`, `unsynced_map`, no `gsRNG`/synced write/`SYNCCHECK`; no synced sim logic derives from membership), so they can be made fully draw-owned. Every edit wraps the existing call in `if (!SimDrawSplit::Enabled()) { …verbatim… }` → flag-off byte-identical.

Sim-thread WRITERS to move to the boundary:
- `CUnit::PreDestruct` → `SetGroup(nullptr)` (Unit.cpp ~150, unit death) — move the prune into `CGame::DeliverBoundaryDeaths` (Game.cpp ~1780, shell readable, team unchanged on death → plain `SetGroup(nullptr)` resolves).
- `CUnit::ChangeTeam` → `SetGroup(nullptr)` (Unit.cpp ~1580, capture/give) — defer a value-captured closure via `UnsyncedBoundaryQueue::Defer`; prune the OLDTEAM handler by unit id (team is newteam by drain time). Add `CGroupHandler::RemoveUnitFromGroups(int unitID)` (team-guard-free, mirrors SetUnitGroup/PushGroupChange). Fold the sibling `selectedUnitsHandler.RemoveUnit(this)` (same class) into the same deferral.
- `CFactory::FinishBuild` → `buildee->SetGroup(GetGroup(), true)` (Factory.cpp ~263, auto-inherit) — defer, re-resolve both ids at drain (`unitHandler.GetUnit`, nullptr-safe if either died in the batch).

Sim-thread READER to de-map:
- `CCommandAI` idle gate reads `owner->GetGroup()` (`unitGroups.find`) on the sim thread (CommandAI.cpp ~1114/1692) — concurrent with a draw-thread emplace/erase this is rehash UB, not just staleness. Replace with a plain `std::atomic<bool> inUiGroup{false}` (relaxed) on CUnit, set in `CGroup::AddUnit`, cleared in `CGroup::RemoveUnit` / `SetUnitGroup(id,nullptr)` / `RemoveUnitFromGroups`; `if (!owner->inUiGroup.load(relaxed)) eoh->UnitIdle(*owner);`. One-frame-stale AI-idle notification is cosmetic (already non-deterministic, injected as net commands).

Scoped out (deprecated, unused by modern AIs): the engine-AI group callbacks `CAICallback::CreateGroup/EraseGroup/AddUnitToGroup/RemoveUnitFromGroup/GetUnitGroup` need SYNCHRONOUS sim-thread access and can't be deferred; if a live AI exercises them under the flip, a narrow lock around `uiGroupHandlers` for those callbacks + the main-thread mutators is the isolated fix.

## Gap B — deep-CAI default-command serving (unparks guihandler)

`CGuiHandler::Update`→`SetCursorIcon` calls `GetDefaultCommand(mouse->lastx,lasty)` essentially every frame in normal play (no active command → context cursor), which bottoms out in `leaderUnit->commandAI->GetDefaultCmd(...)` — a live CAI virtual call, NOT snapshot-served (the PR-30-δ escalation: "GetDefaultCmd core is a live CAI virtual call not resolvable from snapshot rows or the queue cache"). Because it fires every frame, guihandler->Update can't move sim-live without re-parking every frame, so PR 42 left it parked. Also live in the same path: `TryTarget(cmdDesc)` (has its own `ScopedExternalSimPause`), and `GetAvailableCommands` via `LayoutIcons` (cold — selection/command-change driven; `commandAI->GetPossibleCommands()` + `lastSelectedCommandPage`, not in the PR-30 served cmdDesc cache which lacks `lastSelectedCommandPage`).

To fully decouple guihandler for PR 44: serve the default-command (a decoded default-command row per unit, refreshed at the boundary like the command-queue cache) + extend the PR-30 cmdDesc slot with `lastSelectedCommandPage` + a C++ accessor so `GetAvailableCommands` reads the boundary cache. Until then guihandler must stay in whatever parked/quiescent window PR 43/44 provides for the cursor read (it is cheap — one CAI call/frame).

### ESCALATION (2026-07-08, Opus implementation session) — option A as specified is infeasible; ruling needed

Full trace of `GetDefaultCommand → selectedUnitsHandler.GetDefaultCmd → leaderUnit->commandAI->GetDefaultCmd(pointed,feature)` (all 5 CAI overrides + `CUnit::CanTransport` + `CBuilder::CanAssistUnit`/`CanRepairUnit`) shows the §7.2 option-A shape ("decoded default-command row per unit = the value GetDefaultCmd would return, refreshed at the barrier") **cannot be realized faithfully**:

1. **Not a per-unit constant.** `GetDefaultCmd(pointed,feature)` is a pure function of the LIVE cursor target, re-traced by `GuiTraceRay` every draw frame (draw rate). A row refreshed at the barrier (sim rate) can only represent a ≤1-boundary-stale value against a stale target — i.e. it collapses into option C, not the faithful per-frame value.
2. **Faithful per-frame eval can't run draw-side.** Reproducing the tree reaches `CUnit::CanTransport` → **`CSyncedLuaHandle::AllowUnitTransport`** (synced Lua callin, `LuaHandleSynced.cpp:859`) — illegal from draw/unsynced context — plus live mutable reads (`transportCapacityUsed`/`transportMassUsed`/`mass`/`pos`/`isCloaked`/`GetTransporter`; builder `beingBuilt`/`buildProgress`/`soloBuilder`/`health`/`maxHealth`) that race the sim. Reached for transport-capable / builder leaders. So the armed field-pass (which must PROVE served==live GetDefaultCmd) cannot be honestly satisfied for those cases.

Everything else in the tree is row-servable; only the transport branch (synced Lua) is the hard wall. `GetAvailableCommands` (descs + `lastSelectedCommandPage`) is fully feasible and independent of this.

**Options presented to operator:**
- **A' (recommended): sim-side standing-query eval via the PR-35/38e trace-reply channel.** Draw registers a standing default-command query per frame (leader is draw-owned selection; pointed/feature ids or the mouse ray); the SIM evaluates the exact live `GetDefaultCmd` at its frame edge (AllowUnitTransport etc. run legally sim-side); reply rides the epoch (§7.3 already ruled query/reply rides WITH the epoch). Faithful values, ≤1-boundary latency — same staleness class already blessed for `TestMoveOrder`/`ClosestBuildPos` (§1.7).
- **C (task's named fallback): barrier-cached decoded cursor**, ≤1-boundary stale, against the last-known (barrier-time) mouse target.
- **A-partial + defer:** land the feasible `GetAvailableCommands` half now (`lastSelectedCommandPage` + C++ accessor over the served descs), defer the `GetDefaultCmd`/guihandler-unpark half to A'/C. NB: guihandler cannot fully unpark from this PR regardless — `SetCursorIcon` also reads `TestUnitBuildSquare` (blocking map, unparked) and `GuiTraceRay` (trace-channel prereq).

**RULING (2026-07-09, operator):** A′ — implement the default-command as a **sim-side standing-query / reply channel** (single latest-value slot keyed on nothing but the current cursor query, NOT the pos-float-keyed map, so it never hits the pos-form persistent-miss deviation). Evaluated at the SimDrawBarrier today (sim parked → faithful, 0–1 draw-frame latency in all three regimes: normal, paused, FF — the barrier runs every draw frame), and shaped to move to the sim frame edge under the PR-44 flip with no redesign (draw reads the reply from the published epoch, zero draw-side stall; the park-wait converts to ≤1-sim-frame staleness). Operator directive: "whatever gets us to #3 [the producer flip] is good." Rationale: the query/reply channel is flip-aligned; the barrier park-wait it inherits today is pre-existing (every draw frame already parks) and is exactly what the flip removes.

**Scope decided (operator-delegated):**
1. `GetAvailableCommands`/`LayoutIcons`: add `lastSelectedCommandPage` to the PR-30 `UnitCmdQueueSlot` + a C++ accessor over the already-served descs. Independent, feasible now.
2. `GetDefaultCommand`: single-slot sim-side query/reply — the barrier does `GuiTraceRay` (folds the trace in for THIS path) + `leaderCAI->GetDefaultCmd`, publishes `{cmd, pointedID, featureID}`; `GetDefaultCommand` reads the reply and drops its internal `ScopedExternalSimPause`. Armed `SnapshotDiffGate` field-pass proves reply == live `GetDefaultCmd`. Query registered only when the cursor path needs it (no unconditional per-frame trace).
3. Fold `guihandler->Update` into the sim-live (post-`ReleaseSimPause`) set, `shrinkWindow`-conditional (flag-off byte-identical). The every-frame context-cursor path is now served → no park; the remaining rare live reads keep narrow internal parks: `TryTarget` already self-parks; wrap `SetCursorIcon`'s `TestUnitBuildSquare` (minimap build-proxy branch, GuiHandler.cpp:1114) in a `ScopedExternalSimPause`. Fully unparking those two is the separate trace/placement-channel prereqs.
