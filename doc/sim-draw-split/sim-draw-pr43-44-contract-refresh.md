## §1 The epoch package — complete channel list from landed reality

An **epoch** is everything one barrier currently produces, as one versioned, immutable-after-publish unit: `{u64 epochId; frame span [firstSimFrame, lastSimFrame]; the channels below}`. N-buffered ring (start N=3), refcount-retired: draw acquires the newest COMPLETE epoch (ref++), releases the previous (ref--); sim recycles a slot only at refcount 0 ("retired"). `epochId` is monotonic across the game (never reset mid-game; `ClearCaches`-class teardown resets it with everything else) — it replaces `SimSnapshot::Generation()` as the cache key everywhere (§2.5).

Channels, each with representation + retirement rule:

1. **SimSnapshot row namespaces** — `UnitRows`/`ProjectileRows`/`FeatureRows` (due-checked) + `TeamRows`/`PlayerRows`/`GlobalRows` (unconditional) (SimSnapshot.h:218/652/759/880/989/1042). Flat-copied per epoch (today's double buffer becomes the ring's slots). CAVEAT — not everything in these structs is flat: the rules-params mirrors (`GlobalRows::gameRulesParams`, `TeamRows::teamRulesParams`, `PlayerRows::playerRulesParams`, `UnitRows::unitRulesParams`, `FeatureRows::featureRulesParams`) are per-boundary FULL `LuaRulesParams::Params` map copies (PR 38/38c ruling — see drift §5.4), and `TeamRows` carries customOpts/statsHistory-class strings/maps. At N=3 these are the dominant memory/copy multiplier → §6.1. Retirement: rows die with their epoch slot (overwritten on recycle).
2. **Dead-in-batch row retention (DEAD_THIS_BATCH)** — the tri-state validity from `pr38b-flip-wip` (`SimSnapshotValid{INACTIVE,ACTIVE,DEAD_THIS_BATCH}`, `MarkDeadThisBatch`/`ClearDeadThisBatch`, dead-id lists per kind with the projectile synced-namespace guard from `fd41dbdd92`). Epoch-form change (supersedes the 38b post-publish marking): the PRODUCER extracts dying ids' rows directly from their DeferredObjectDeleter shells at the frame edge (shells are readable by the PR-13 contract), so a DEAD_THIS_BATCH row is genuinely the object's at-death state — this deletes the 38b "genuineness guard" class (`bbdab4a5f4`: the double-buffered front slot held 2-boundary-stale or foreign data for young units → null-defID SIGSEGV) by construction instead of by guard. Validity rule: DEAD_THIS_BATCH reads as valid only while that epoch's record dispatch runs (the drain-window successor, now a per-epoch dispatch bracket); INACTIVE-guarded so same-batch id reuse keeps the new object ACTIVE. Retirement: cleared when the epoch retires (rekeyed from the 38b "barrier ack" clear).
3. **Render-event records + deferred-unsynced-dispatch records** — `RenderEventQueue::Record` (RenderEventQueue.h:84: create/destroy/LOS/ghost, plain data) and the `UnsyncedBoundaryQueue` closures (UnsyncedBoundaryQueue.h) for the epoch's frame span, in total fire order. Never skipped: an unconsumed epoch's records FOLD into the next published epoch, order-preserved (exactly today's catch-up batch drain, producer-side). Includes the boundary-death id lists consumed by `DeliverBoundaryDeaths` and the event-time captures (fire-time `CaptureCmdQueueEvent` slots, LOS-exit captured losStatus/allyTeam — LuaSnapshotServe.h:281–332, SimSnapshotLosEvent SimSnapshot.h:1232). Retirement: records are consumed at dispatch (epoch-consume), but the ids they reference must stay servable until dispatch completes → they pin the epoch's rows + shells (channel 2 + §2.3).
4. **DrawMapMirrors payloads** — the dirty layers among: 7 LOS types × allyteams + globalLos, terrain-types, smooth mesh, orig heightmap, typemap, metal distribution, metal EXTRACTION map (PR 42a), blocking map (PR 29) (DrawMapMirrors.h). Landed granularity is whole-layer dirty flags/versions, NOT rects (enumerated deviation, DrawMapMirrors.h:41). Under the producer flip the sim must copy dirty layers at its frame edge (the single draw-owned mirror can no longer copy from live sim at consume time). Representation decision → §6.4: per-epoch layer copies vs refcount-shared immutable layer blocks (clean layers share across epochs; LOS + blocking + extraction churn near-every-frame so they are effectively copies either way). Fold rule for skipped epochs: dirty sets OR together (order-insensitive because whole-layer). The heightmap rect queue (`readMap->UpdateDraw`, barrier step 6) joins this channel: sim appends rects into the epoch, draw applies them + fires `UnsyncedHeightMapUpdate` at consume.
5. **Command-queue / cmdDesc / worker-task cache** — today a singleton `std::vector<UnitCmdQueueSlot>` refreshed generation-gated at the barrier, version-keyed on the CCommandQueue content-version + `GetCmdDescVersion` (LuaSnapshotServe.cpp:6061–6108, `RefreshCommandQueues` reads LIVE queues under the park). Epoch form: the shelved PR-30 design (branch `worktree-wf_5d30e3ba-f92-2`, `e6d88812e7`) — per-unit refcounted immutable blocks, clean units share across epochs (ref++), dirty units get fresh blocks at extraction; queue and desc blocks split so a pop doesn't recopy descs. Refcount must be atomic (cross-thread release at retirement). Retirement: block ref-- when its epoch retires.
6. **Piece caches** — `RefreshPieces` (LuaSnapshotServe.h:416, generation-gated, captures live piece transforms + static model metadata at the barrier) AND the PR-8 `ExtractTransforms` SSBO staging (`transformsMemStorage` — NOT a SimSnapshot namespace; reads live `LocalModelPiece` state in the UPD pass). BOTH are live-reading extraction that must move to the sim-side frame edge under the flip. Static metadata (names, hierarchy, script→piece maps) is model-immutable → captured once at the creation record, shared. Dynamic transforms: per-epoch flat capture (measured churn ~0.5–0.8 MB/frame at 2–3k units, 33–35% churn — S0). The specs' epoch definition omitted this channel entirely (drift §5.10) → §6.6 for the SSBO-staging representation.
7. **Trace + placement query/reply channels** — DISTINCT from the ring (flagged in LuaSnapshotServe.h:561 and :628). Direction draw→sim→draw: the draw side enqueues `{owner,weapon,target-form}` trace queries and `{kind,unitDefID,pos,facing}` placement queries; the sim evaluates the EXACT live predicates at its frame edge (`EvaluateTraceQueries`/`EvaluatePlacementQueries` move from barrier steps 3c/3d to sim-side pre-extraction); replies publish with (or alongside) the epoch. Under the flip the pending queue becomes a real cross-thread channel (mutex/MPSC — draw-side writers, sim-side drain). PR-43 scope per the Batch-4 operator ruling: re-key per callout — `TestBuildOrder` by build-grid-SNAPPED pos (value-safe: result is grid-quantized); `ClosestBuildPos`/`TestMoveOrder` (+ pos-form traces) by a STANDING-LATEST-QUERY model (draw registers its current per-(callout,unit) query, sim evaluates the most-recent pos each edge, reply is ≤1 boundary late but never-default). Retirement: replies are last-value-wins maps, self-pruning (already landed); they don't pin epochs.
8. **Ctrl-poke boundary-apply queue** — `QueueBoundaryApply`/`DrainBoundaryApplies` (LuaSplitContract.h:82/98), today drained at barrier step 2b. Direction draw→sim. Under the flip: consumed by the SIM thread immediately before extraction (freshness by construction — deletes the step-2b `MarkMutatedOutsideFrame` poke). Cross-thread queue like channel 7.
9. **Model-upload GL half** — sim-thread model loads split CPU/GL at the parse/upload seam (27b commit c); the GL uploads are main-thread-only. Epoch rule: the upload requests ride the epoch (or a side queue drained first), and the CONSUMER services all pending uploads BEFORE dispatching that epoch's creation records — preserving today's step-0b-before-step-1 ordering guarantee.
10. **Rules-param payloads** — see channel 1 caveat; called out separately because the plan treats them as a delta channel and landed reality is full copies (drift §5.4). Epoch treatment decision → §6.1 (accept N× full copies vs dirty-versioned shared blocks per the queue pattern).

Draw-side derived state that is NOT in the epoch but keys on it: `SnapshotPickGrid` rebuild, the lazy team-unit index, the PR-40/41 `QuadMembership` mirrors, the event-time override installs — all rebuilt/validated at epoch consume, keyed by `epochId` (today `Generation()`; §2.5).

## §2 PR 43 — epoch infrastructure (mechanism swap, consumer unchanged)

Scope: the boundary package becomes the explicit epoch of §1, produced AT THE BARRIER UNDER THE PARK exactly as today. The consumer still runs in `CGame::Draw`; production and consumption stay lockstep (at most one live epoch outstanding), so N-buffering is exercised but not yet load-bearing. Flag-off byte-identical; flag-on value/timing-identical. A pure representation change.

1. **The ring.** N=3 epoch slots; `simSnapshot.Update()` + `RefreshCommandQueues` + `RefreshPieces` + mirror drain + record packaging fill the next slot; publish = the slot becomes newest-complete; draw acquires (ref++) and releases the previous (ref--). Under 43's lockstep this is a pointer rotation with the same values the double buffer held. The `front/back` double buffer, `cmdQueueCacheGeneration`, `pieceCacheGeneration` and the mirrors' drained-version scalars become per-slot state.
2. **DeferredObjectDeleter release rekeyed to epoch retirement.** Replaces BOTH the end-of-Draw `ReleaseAcked()` (Game.cpp:2190) and the split-only relocated-ack special case (barrier steps 2 vs 8). New rule: a destroy record pins its shell to its epoch; ACK (destruct + poison, DeferredObjectDeleter.h:86) when the consumer finishes dispatching that epoch's records; RELEASE (pool return, :89) when the epoch retires. The valve (`Defer()` headroom check) becomes "sim waits for epoch retirement" — under 43's lockstep that is behaviorally today's valve service (the epoch retires within the same Draw). The ack/release pair stops bracketing "one Draw" and starts bracketing "one epoch's lifetime" — with lockstep consumption these coincide, which is what makes 43 flag-on-identical.
3. **Dead-in-batch rows land here, inert-but-armed** (resurrect from `pr38b-flip-wip`, amended per §1.2: producer-side shell-sourced extraction of dying ids, no genuineness guard; keep the `fd41dbdd92` projectile namespace guard as the id-list filter). The barrier dispatches (step 7) STILL run under `barrierLive` ScopedLiveException reading live — 43 does NOT convert them (that is 44's half-b; converting it early is exactly what 38b proved fatal without creation/event-time serving). DEAD_THIS_BATCH therefore only replaces the shell-fallback READ maps (`ResolveBoundaryDeadUnit/Feature`, `ShellFallbackUnit/Feature` — SimDrawSplit.h:60–66, RenderEventQueue.h:160–171) for the ROW-served twins; the pointer-returning `LuaUtils::IdToObject` path keeps its shell fallback until the SCOPE-1/plan-PR-39 id-keyed storage lands (the `bbdab4a5f4` lesson: deleting it null-crashed `FeatureDestroyed`). Shell MEMORY lifetime: unchanged mechanism, now epoch-keyed (item 2).
4. **Query/reply keying fix** (operator-ruled, Batch-4): grid-snapped `TestBuildOrder` key + standing-latest-query for `ClosestBuildPos`/`TestMoveOrder` (and pos-form traces). Landable inside 43 because it edits the channel, not the threading.
5. **Cache re-keying.** Every `Generation()`-keyed draw cache (team-unit index, QuadMembership mirrors, pick grid, cmd/piece caches per item 1) keys on `epochId`. `LuaSnapshotServe::ClearCaches`' aliasing rationale (generation resets across games) dissolves — epochId is u64 monotonic per game and slots are explicit.
6. **Invariants (escalate if threatened):** flag-off bit-identical (resim ×2 both replays); flag-on value-identical (same served values, same event dispatch order/timing — the epoch is a container swap, not a semantics change); records never skipped, total fire order preserved; every id referenced by an epoch's records is servable from that epoch (ACTIVE or DEAD_THIS_BATCH rows) — add the ARMED ASSERT for this (§3.6) now, it is 44's make-or-break invariant and 43 can prove it holds under the park first.
7. **Gates:** the standing battery + DEBUG-headless + TSan segment re-run (lifetime model changed: ack/release rekeyed) + armed diff-gate both replays + strict SplitDrawContract=2 zero-denial re-proof + headful 2×/replay (widget-error watch — the 38b class is headful-GL4-only; agents misdiagnose it headless, orchestrator instruments).
8. **Telemetry to land with 43:** per-epoch payload bytes by channel + ring occupancy (`/epochstats` or BoundaryStats extension) — the §6.1 memory ruling and 44's pacing tuning need measured numbers.

## §3 PR 44 — the producer flip

Scope: extraction moves onto the sim thread; draw never parks in gameplay. This is the program's structural payoff (the parked window disappears entirely, not the PR-42 ~10%).

1. **Producer.** At each sim frame edge (the `YieldIfPauseRequested` point in `SimThreadProc`, Game.cpp:1883), IFF the previous epoch has been consumed: drain the ctrl-poke queue (channel 8), evaluate standing/pending queries (channel 7), then produce the epoch — `Extract*` all namespaces (+ shells for dying ids), queue/piece block refresh, dirty mirror layer capture, record packaging — and publish. Precedent that `Extract*` is sim-thread-runnable: `HashCompletedFrame` already runs the full extraction on the sim thread today (SimSnapshot.cpp:355–371); the one exception is `CacheMapStartPositions` (MapParser, must stay main-thread — one-time, move to load).
2. **Pacing.** Skip-if-unconsumed: extraction cost is paid at min(sim rate, draw rate); a catch-up burst pays ~one extraction per draw frame (today's batching, producer-side). Net-mutation-between-frames (team transfers, PLAYERINFO, boundary pokes): the sim thread OWNS `ClientReadNet`, so it re-marks/re-extracts the pending epoch itself — the `MarkMutatedOutsideFrame` successor is producer-local and closes today's due-check blind spot by construction.
3. **Consumer.** `CGame::Draw` acquires the newest complete epoch (no park, no handshake): service GL uploads (channel 9), dispatch the epoch's records in fire order (creation/destroy/LOS/ghost + boundary deaths + a0 closures), apply mirror layers/rects, rebuild derived caches, run the deferred unsynced callins — ALL against epoch data (see item 6). "No new epoch" = re-render interpolating from the current one (the no-op boundary falls out as steady state). Consumers outside Draw (input handlers) read the currently-held epoch, same ≤1-frame staleness contract as today (SimSnapshot.h:137–140).
4. **Backpressure + valve.** Sim runs ahead ≤ N-1 unretired epochs (replaces `LastBoundaryFrame()+1`, NetCommands.cpp:293 — at N=3 the 1× behavior is unchanged-or-looser; free-run knobs unchanged). Pool valve = wait for epoch retirement (shells pinned per §2.2); the valve's in-place drain service (Game.cpp:1967) is DELETED — the sim can always finish its frame by waiting for draw to consume+retire, and draw never blocks on sim (deadlock argument: draw's acquire never waits; sim's only waits are ring-full and pool-headroom, both released by draw's consume/retire which needs nothing from sim).
5. **RequestPause demoted to lifecycle-only:** saves/checkpoint serialize (LoadSaveHandler.cpp), Lua handle create/reload/kill (the DECL_*_HANDLER brackets), teardown, armed test gates (the diff gate's quiescent field passes park per compare window — test-only). EVERY OTHER `ScopedExternalSimPause` site becomes a REAL mid-gameplay sim-thread park and must be dispositioned before 44 ships (§4.5 inventory; the per-frame ones gate the whole win).
6. **THE 38b RESOLUTION — creation-time + event-time deferred serving (make-or-break).** What 38b proved (gate `bthgtfct8`/`bhfd6lsho`, revert `981cbfea44`): removing `barrierLive` so the deferred create/damage/event handlers read published state nil-stormed headful (4594→6812 lua errors: `FeatureCreated` featureDef nil, `UnitCreated`/`UnitDamaged` compare-nil, `gui_healthbars` FeatureReclaim) — and the nils persisted even after restoring `barrierLive`, i.e. the DEAD_THIS_BATCH/drain-window lifetime changes interacted with deferred dispatch in a way that was never confidently root-caused before the revert. Under 44 there is NO park, so "restore the live exception" ceases to exist as a fallback: the deferred handlers CANNOT read live sim, period. PR 44 must therefore supply, as hard contract:
   - **(a) The id-coverage invariant:** for every id referenced by any record or a0 closure in epoch E, E serves that id — ACTIVE rows (alive at E's edge; a just-created object IS extracted, because extraction runs at the frame edge after the batch's creations) or DEAD_THIS_BATCH rows (shell-sourced at-death values for created-and-died / died-in-batch ids). No record may dispatch against an unservable id. Enforced by an ARMED GATE (a per-record pre-dispatch check that its id resolves in E), landed in 43 (§2.6) — this converts the 38b failure class from "headful widget-error attrition" into a deterministic gate failure.
   - **(b) Event-time presentation, generalized:** the landed override machinery — fire-time `CaptureCmdQueueEvent` + `ScopedCmdQueueEventOverride` + top-of-callout consults (`CmdQueueEventOverrideActive`/`LosEventOverrideActive`, LuaSnapshotServe.h:281–332) and the LOS-exit visibility/retained-pos serving (38l, `SimSnapshotLosEvent`) — is the pattern, NOT the 38h blanket-reassert (reverted; it force-nil'd handlers' unrelated reads). Extend fire-time capture to every deferred event whose handler reads state the event changed: creation records already carry def/team/pos args; UnitDamaged/FeatureReclaim-class events capture their value args at fire time; handlers' FOLLOW-UP reads hit the epoch rows (at-edge state — the already-blessed tier-(a) deviation; nils are defects, staleness is contracted).
   - **(c) Dispatch-window scoping per epoch:** the drain window (today a global main-thread bool) becomes "epoch E's records are dispatching" — DEAD_THIS_BATCH validity and event-time overrides scope to that bracket, and E cannot retire until its bracket closes.
   - **(d) Verification discipline:** the class is headful-GL4-only and draw-timing-flaky — the 44 gate runs the headful matrix MULTIPLE times per replay (38j/38l precedent), orchestrator-instrumented, plus a windowed live-skirmish session; a single clean run is not proof.
7. **Camera-dependent culling** (`UpdateDrawFlags` and the visibility passes) stays draw-side and reads epoch positions/drawer storage — requires the SCOPE-1 render records + projectile pass conversion (§4.3/4.4) so no pass resolves through `unitHandler`/`featureHandler`/`projectileHandler`. `ExtractTransforms` is camera-INDEPENDENT (PR-8 contract) and moves to the producer (§1.6). `BuildSplitResolveCache` (barrier step 1c — a live handler-table walk) is deleted by the prereq, not ported.
8. **Sim-side unsynced-work rule hardens:** everything the sim fires for the draw side defers (already true, `UnsyncedBoundaryQueue`); NEW audit obligation — drain-time re-resolution inside a0 closures and boundary-death delivery must not touch sim-owned handler tables (they run concurrent with the sim now): wait-AI drain-time liveness re-checks, the Gap-A factory-group re-resolve (`unitHandler.GetUnit` at drain), and any closure that re-resolves ids live convert to epoch-row checks or shell reads. Grep-audit table in the 44 commit (choke-point rule).
9. **Gates:** the full battery — resim ×2 both flags; DEBUG headless; TSan segment (the split's machinery must stay clean; the tolerated §C torn-read families are enumerated); armed diff-gate (flag-off; the dual-run's live leg is gone for good flag-on); strict zero-denial; windowed dogfood both replays + live skirmish; ON-vs-OFF frame-time telemetry; headline = the frame grapher's Parked slice ≈ 0 outside lifecycle events; §3.6d headful cadence.
