## Established facts (from the three surface maps, 2026-07-09)

- DRAW-WINDOW passes (`DrawOpaque/Alpha/Shadow*`, `Should*`, VAO `AddToSubmission`, minimap/screen icons, ghost buildings, `DrawUnitModelBeingBuilt*`, `LocalModel::Draw`, Lua-material bins) run AFTER release, concurrent with the running sim under the flip. ## The render record

Add to each drawer-data class (`CUnitDrawerData`, `CFeatureDrawerData`) an id-keyed `std::vector<RenderRecord>` (indexed by object id; parallel to `drawFlags`/`drawPositions`). NEVER erased on `DelObject` — stale-until-id-reuse, exactly like `drawFlags`/`drawPositions`. That staleness window is what gives the deferred-dispatch id-coverage that retires the `IdToObject` shell fallback (a died-in-batch id still resolves its at-death record through the dispatch), independent of PR 43's DEAD_THIS_BATCH rows (which have NOT landed on this branch — SCOPE-1 supplies its own coverage; §4.3 "43 can precede it").

`UnitRenderRecord` fields: immutable {`const S3DModel* model`, `const UnitDef* def`}; mutable (refreshed each producer Update, new `UpdateRenderRecord(u)` beside `UpdateObjectDrawFlags`) {`int team`, `int allyteam`, `unsigned short losStatusMyAllyTeam`, `uint8_t engineDrawMask`, `float buildProgress`, `bool beingBuilt`, `int buildFacing`, `bool luaDraw`, `float radius`, `bool isInVoid`, `float3 pos`}; plus `LuaObjectMaterialData luaMaterialData` (evicted, §Eviction) and per-piece `std::vector<std::vector<uint32_t>> lodDispLists` (evicted).
`FeatureRenderRecord`: immutable {`const S3DModel* model`, `const FeatureDef* def`}; mutable {`int team`, `uint8_t engineDrawMask`, `bool luaDraw`}; plus the evicted luaMaterialData/lodDispLists.

Accessors: `GetRenderRecord(int id)` const-ref, bounds-checked returning a static zero record for unregistered ids (same pattern as `GetDrawFlagState`).

## Eviction of luaMaterialData + lodDispLists (PR-10 deferred)

Both are draw/Lua-thread-only (never sim-touched), CR_IGNORED, so no creg migration. The eviction removes them from the sim object's resident memory and reaches them by id.
- `luaMaterialData`: lives in the render record. Remove `LocalModel::luaMaterialData` + `LocalModel::GetLuaMaterialData()`. Replace `CSolidObject::GetLuaMaterialData()` — the accessor has no objType, so route via a drawer call. Call sites in `LuaObjectDrawer`/`LuaObjectRendering`/`LuaOpenGL` MOSTLY carry `LuaObjType objType` already → replace `obj->GetLuaMaterialData()` with `LuaObjectDrawer::GetLuaMaterialData(objType, obj->id)` (dispatches to unit/feature drawer record). The objType-less consumers (`LocalModel::Draw`, `LocalModelPiece::DrawLOD`) get the record/material threaded down from the drawer draw pass (they are only reached from the drawer's own Lua-material draw path, which knows objType).
- `lodDispLists`: remove `LocalModelPiece::lodDispLists`; store per-object per-piece lists in the render record (`lodDispLists[pieceIndex][lod]`). `LocalModelPiece::DrawLOD(lod)` → needs the per-object list: thread the record's per-piece list pointer down through `LocalModel::DrawPiecesLOD` → `DrawLOD`. `SetLODCount` resize + `LuaObjectRendering::SetPieceList` write reroute to the record. Preserve the invariant that luaMaterialData LOD count and lodDispLists sizes stay lockstep (validated together via `ValidLOD`).
