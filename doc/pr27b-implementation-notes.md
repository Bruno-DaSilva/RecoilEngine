# PR 27b implementation notes (working doc)

Status: design settled 2026-07-06 after the full prerequisite audit; implementation in progress on `bruno/poc-split-sim-draw`. This file is the working record for the split itself — decisions, discovered scope, and the commit plan. It feeds the eventual PR-27b DONE note in `sim-draw-thread-decoupling-research.md` and is deleted/absorbed when that lands.

## Decisions (settled here, referenced by the commits)

1. **Pause-window placement — no reorder, v1.** The window is `[top of CGame::Draw .. end of worldDrawer.Update()]`: `SimDrawBarrier()` stays the first thing in Draw exactly as PR 26 landed it, and the release point is right after `worldDrawer.Update(newSimFrame)` inside `UpdateUnsynced` (before the uploaders — they read extracted storage only). Everything between runs with sim parked, in the exact flag-off order: the PR-26 "deferred second half" question is resolved by *extending the window*, not by moving the camera update. Consequence accepted for v1: widget `Update` callins and infotex run inside the window, so their cost is boundary cost — measured by the gate-5 telemetry, and the documented optimization path (reorder camera+extraction ahead of widgets) stays available if the number is bad. Rationale: the alternative reorder changes flag-ON ordering semantics in ~6 places; extending the window changes none.
2. **ThreadPool strategy — shared pool + side-exclusivity, not partition/two-pools.** for_mt work distribution is already MPMC-safe (atomic slice counters, per-call-site recycled group pools, per-worker MPMC queues; orchestrator participates via WaitForFinished). Workers execute one slice at a time, so `GetThreadNum()`-indexed scratch is safe under interleaving as long as no scratch array is *concurrently owned* by fork-joins from both threads. The census (LosMap, HAPFS/QTPFS, MoveMath::blockMaps, QuadField temps, gs/WorldObject mtTempNum) shows every sim-scratch consumer reachable from draw code sits inside the pause window (infotex, debug drawers) — side-exclusive by construction once the window covers them. The two real cross-thread instances get fixed directly: TimeProfiler (tid-0 collision on threadProfiles[0] + the unlocked special-timer fast path) and DEBUG asserts documenting the invariant at the scratch entry points.
3. **Backpressure.** Sim consumes NEWFRAME only if `frameNum < lastBoundaryFrame+1` OR free-run (`speedFactor > 1`, `skipping`, `IsSimLagging()`, video capture). The budget logic (msgProcTimeLeft / consumeSpeedMult) runs verbatim on the sim thread — it is rate-integrated so call cadence doesn't change consumption; the per-call wall-time cap just returns to the loop.
4. **Pool-pressure valve** (DeferredObjectDeleter): flag-on, the valve parks the sim thread mid-frame instead of flushing (it may not touch the main-owned queue). RequestPause treats a valve-park specially: drain+ack+release, resume sim, re-wait for a frame-edge park. Flag-on also skips the end-of-Draw ReleaseAcked — slots return at the next barrier's ack (pools are sim-owned; main must not free into them while sim runs).
5. **Sim-fired unsynced work defers to the boundary** (the tier-(a) deviation the compatibility invariants enumerate). One FIFO of closures (order-exact), drained as a barrier step after the snapshot publish: EventHandler dispatches to unsynced clients, Cob2Lua(Batch) to unsynced handles, SendToUnsynced (via a neutral mailbox lua_State), wordCompletion writes, SetDevMode fan-out, and the net-message draw-pokes (mapdraw, countdown UI, GameEnd's UI half). Deferred closures capture args by value + object pointers (PR-13 lifetime: no sim object is freed before the barrier ack).
6. **LuaMemPool**: flag-on, unsynced handles get a second shared pool (synced handles keep gSharedPool). Allocation affinity is per-lua_State so the pools become thread-exclusive. Flag-off: single pool, bit-identical.
7. **GC split**: flag-on, SimFrame's CollectGarbage covers synced clients only; the main-thread timed job covers unsynced only (closes the Game.cpp:340 TODO).
8. **GL request queue** (commit c): sim-side `CModelLoader::Upload` (VBO upload + S3O texture GL) becomes a queued request serviced at the top of the barrier *before* the render-event drain — the creation record and the upload request travel to the same boundary, so no drawer can see an object whose model isn't uploaded. Sim does not block (the CPU parse half is already thread-safe under CModelsLock, which gets its thread-safety re-enabled when the flag is on). Runtime CEG loading is CPU + read-only atlas lookups — stays on the sim thread. ExplosionGenerator's asserts are container guards, not GL: they widen to accept the sim thread (unsynced projectile containers are sim-owned under the split).
9. **Serving expansion is a precondition of flag-ON dogfood** (decision 5 + the 27a live-GL trip inventory: command-queue family 335k, GetTeamUnitDefCount 289k, IsUnitInView 273k, IsUnitSelected 237k, ...). Sanctioned-live reads are races once the thread exists. See commit (d) breakdown in the task list / final DONE note.
10. **Headless honors an explicit SimDrawSplit=1** (default stays off): gate 3 (DEBUG headless replay, flag ON) and the automated flag-ON resim gates require it. "Headless keeps the single-threaded model" holds by default.
11. **Flag semantics**: `SimDrawSplit` (int, default 0). Flag-off takes no new locks (WrappedSync-style toggles for the NetProtocol Peek/Delete gap and CModelsLock) and is byte-identical. Flag-on before the thread-spawn commit lands = single-threaded dress rehearsal of all deferral semantics.

## Commit (b) resolution: ThreadPool needs no partition

The plan offered two pools / partition / fork-join-instance-local scratch. The audit shows the third option is already ~true and the first two would cost worker capacity for nothing:

- Work distribution is MPMC-safe as-is: for_mt uses per-call-site recycled group pools with atomic slice counters (`ForTaskGroup::ctr.fetch_add`), pushes only to per-worker moodycamel queues (the global queue never holds fork-join groups, so the two orchestrators cannot steal each other's slices), and the orchestrator participates via WaitForFinished with its thread-local tid. Two concurrent fork-joins interleave per-worker *sequentially* — a worker runs one slice at a time — so `GetThreadNum()`-indexed scratch is only hazarded when the same array is concurrently owned by fork-joins from both threads.
- The scratch census (LosMap tables, HAPFS/QTPFS per-thread state, MoveMath::blockMaps, QuadField temp vectors, gs/WorldObject mtTempNum) shows every sim-scratch consumer reachable from draw code sits inside the pause window (infotex updates, the drawer extraction) or is flag-gated dark (debug drawers) — side-exclusive by construction. Draw-side fork-joins outside the window (RoamMeshDrawer, particle sorting, font gen) touch draw-owned data only.
- The two genuine cross-thread instances were fixed directly in commit (a): TimeProfiler's lock-free special-timer path (the "Sim"/"Draw" pops now lock under the split; the tid-0 threadProfiles writes were already under profileMutex whenever they can happen) and GetTimeRecord's unlocked read.
- `CSyncChecker::inSyncedCode` moves to the sim thread; the worker-side read in DoTask is a scheduling heuristic (benign). The tid==0 assert in `CSyncChecker::debugSyncCheckThreading` holds (the sim thread's threadnum is 0, same as any orchestrator).
- `IsInMultiThreadedSection` is thread-local and keeps its meaning per the research doc.

Deliberately NOT given a distinct threadnum: giving the sim thread a reserved tid would index past arrays sized by `GetNumThreads()` (HAPFS maxResPFs et al). tid 0 is correct — both orchestrators use slot 0 of *different* (side-exclusive) scratch arrays.

## Flag-ON shakeout log (2026-07-06)

First full-length clean flag-ON resim: Rosetta f=44537, 0 DESYNC, wall 4:22 (commit `b929576261`). Defects found by iterating the crashing runs, each now fixed:

1. **Pregame LuaUI VM corruption** — NETMSG_LUAMSG ran `luaUI->RecvLuaMsg` on the sim thread (BAR floods LuaUI messages at gamestart); crashed a concurrent DrawScreen inside `luaV_execute`. Boundary-deferred, gate decision captured at fire time. Same class: `ShockFront` from `CGameHelper::Explosion`, the unsynced leg of `/luarules` chat (`CSplitLuaHandle::GotChatMsg`).
2. **Post-release id→object resolution through sim-owned tables** — the draw passes resolve drawer-container ids per pass (`ResolveProjectileHandle` reads `FreeListMapCompact` maps the sim rehashes; unit/feature handler slots null at sim-time destroy while bins still hold the id). Fixed with boundary-built resolve caches (ModelDrawerData splitResolveCache + ProjectileDrawer twin), rebuilt with the sim parked right after every drain.
3. **The tid-0 scratch collision is real** — the commit-(b) audit's "side-exclusive by construction" claim missed the still-live Lua spatial walks: `GetUnitsIn*` from draw context uses quadfield scratch slot `GetThreadNum()==0`, colliding with the sim thread's own queries; the corrupted GetQuads scratch crashed `CQuadField::MovedUnit` ON THE SIM THREAD. Main-thread queries under the running split now take a reserved extra slot (`ThreadPool::MAIN_SPLIT_SCRATCH_SLOT`; quadfield caches + gs/WorldObject mtTempNum arrays grew by one). The commit-(b) section above stands corrected by this entry.
4. **Sanctioned-live ends at the flip** — with the sim thread running, sanctioned live reads walk containers under mutation (crash-class). `DenyLiveRead` now denies every unserved live read while the sim thread runs; commit (d) serves the hot families back. The armed diff-gate dual-run disables itself under the running split (its live leg's quiescence premise is void; the barrier field passes stay armed).
5. `CheckStack` diagnostics on the synced states skip while the sim thread owns them.
